# Architecture Decision Records

An accepted ADR is immutable. It is not edited to reflect a change of mind and it is not deleted when it turns out to be wrong — a new ADR supersedes it, the old one's `status` line is updated to point at the successor, and both stay in the tree. That status line is the only permitted post-acceptance edit.

The record of paths this project rejected is worth more than the record of paths it took, because the rejected ones are the ones someone will propose again next quarter.

## Why this directory exists at all

This project is developed largely by AI across many sessions with no shared memory. Without written rationale, a later session will "improve" a deliberate trade-off it does not understand, and the reasoning that justified it is gone. An ADR is the only artefact that survives that: the code says *what*, the tests say *that it still holds*, and only the ADR says *why, and what was rejected to get here*.

Which changes require one is stated in [`../../CONTRIBUTING.md`](../../CONTRIBUTING.md) §3. The short version: a decision that constrains future changes.

## Writing one

Write new records from [`.claude/templates/adr.md`](../../.claude/templates/adr.md), or run `/adr`. Numbers are four digits, zero-padded, and **never reused** — a reused number makes two decisions share an address, and every cross-reference to it then resolves to whichever file the reader happened to open.

The load-bearing section is **Alternatives considered**, and specifically the strongest rejected alternative, argued at its full strength before it is rejected. An ADR whose alternatives all read as obviously bad is an ADR that considered none of them, and it is worse than no record: a future reader cannot tell whether the rejection still holds, so they either re-litigate it from scratch or accept it on authority. Both outcomes are the failure this directory exists to prevent.

"Do nothing" is argued explicitly and costed. It is frequently the right answer and nobody writes it down.

Every ADR also carries a **revisit trigger** that a monitoring system or a scheduled review could evaluate without judgement, and a **verification** block naming both the value that would confirm the decision and the value that would refute it. A decision with no verification date is a decision that never gets graded, and ungraded decisions accumulate.

## What is checked mechanically

An index maintained by hand drifts, and a reader who consults a stale index, finds an answer and stops looking is worse off than one who found no index at all. So the table below is generated from the files, and `tools/checks/adr_index.py` — run by `make check` and by CI's fast gate — fails on:

- a filename that does not match `NNNN-<kebab-slug>.md`, or whose number disagrees with the `number` in the front matter;
- a reused number;
- a missing required front-matter key, a non-ISO `date`, or a `status` outside `proposed`, `accepted` and `superseded by ADR-NNNN`;
- a `superseded_by` naming a record that does not exist, or one whose successor does not carry the reciprocal `supersedes` — a supersession recorded on one side only leaves two live contradictory decisions with nothing saying which won;
- a `status` line and a `superseded_by` field naming different records;
- an index table that does not match what the front matter generates.

Numbers may have gaps, and the check does not require the sequence to be contiguous — 0013 is reserved for [#21](https://github.com/ismetcahangirov/financeKing/issues/21).

Regenerate the table with:

```bash
uv run python tools/checks/adr_index.py --write docs/adr
```

Do not edit it by hand. The generator owns everything between the sentinel comments and overwrites it; everything outside them is prose it will not touch.

## Where else decisions are recorded

[`.claude/knowledge/decisions-log.md`](../../.claude/knowledge/decisions-log.md) is the one-screen **index** of every load-bearing decision, with the alternative each one rejected. It is not a replacement for this directory: an ADR is where a decision is *made* and argued, and the log is where you find out that the argument happened — so a session with no memory of the last one does not reopen a closed question.

A decision may legitimately live in the log with no ADR, because `ARCHITECTURE.md` or `CLAUDE.md` is canonical for many of them. Write the ADR when the decision is next argued about. An ADR written for a decision nobody is questioning is filing, not thinking.
